* keepass-auth-source for emacs
** Introduction
   This provides KeePass as an =auth-source= for emacs.  Once enabled, any
   Emacs feature that uses =auth-source= ([[https://www.gnu.org/software/emacs/manual/html_node/efaq/][smtpmail]], =mu4e=, =erc=,
   =forge=, ...) can read credentials from your KeePass database.

   It talks to a KeePass database using one of two command-line backends:

   - =keepassxc=  (default)  [[https://keepassxc.org/][KeePassXC]]'s =keepassxc-cli=, a cross-platform
     client that works on GNU/Linux, macOS and Windows.
   - =kpscript=              KeePass's [[https://keepass.info/plugins.html#kpscript][KPScript]], a *Windows-only* scripting
     plugin that drives an installed [[https://keepass.info/][KeePass]].

   The backend is chosen automatically by =keepass-auth-source-enable=,
   preferring =keepassxc-cli= when it is available, and can be forced with
   =keepass-auth-source-cli=.
** Requirements
   No Emacs packages are required (dash.el and s.el are no longer needed).

   At least one of the following external programs must be on your =exec-path=:

   - =keepassxc-cli=  (cross-platform; recommended)
   - =keepass= and =kpscript=  (Windows-only)
** Installation
   Add keepass-auth-source to your =load-path=.
** Setup
   1. Add =(require 'keepass-auth-source)= to your init file
   2. Add =(keepass-auth-source-enable)= to your init file to enable using KeePass database files as an auth-source

   #+BEGIN_SRC elisp
     (require 'keepass-auth-source)
     (keepass-auth-source-enable)
     (add-to-list 'auth-sources "~/.emacs.d/passwords.kdbx")
   #+END_SRC

   The auth-source will ask for the password for the kdbx file when trying to use it as an auth source.
** How auth-source finds an entry: the canonical KeePass fields
   =auth-source-search= is called by Emacs with a specification of *keys* like
   =:host=, =:user=, =:port=, =:title= and so on.  keepass-auth-source maps those
   onto the **five canonical KeePass entry fields** that =keepassxc-cli= can
   actually search:

   | Canonical KeePass field | searched by keepassxc-cli as |
   |--------------------------|-------------------------------|
   | Title                    | =title:=                    |
   | UserName                 | =user:=                     |
   | Password                 | =password:=                 |
   | URL                      | =url:=                      |
   | Notes                    | =notes:=                    |

   An entry is only found if its canonical field *contains* the value you are
   searching for.  For example, searching for =:host "smtp.gmail.com"= looks
   in the **URL** field, and searching =:user "you@gmail.com"= looks in the
   **UserName** field.

*** Aliases: how the auth-source keys map to the canonical fields
   The auth-source keys are aliases for the canonical KeePass fields:

   | auth-source key | maps to canonical field | keepassxc-cli term used |
   |-----------------|-------------------------|-------------------------|
   | =:host=         | URL                     | =url:HOST=             |
   | =:host= + =:port= | URL                    | =url:HOST:PORT=       |
   | =:user=         | UserName                | =user:USER=            |
   | =:title=        | Title                   | =title:TITLE=          |
   | =:password=     | Password                | =password:PASSWORD=    |
   | =:notes=        | Notes                   | =notes:NOTES=          |

   keepassxc-cli's =search= command ANDs together space-separated,
   field-scoped terms, so when several keys are present they are combined
   into a single query.  For example, searching =:host "smtp.gmail.com"
   :user "you@gmail.com" :port 465= runs:

   #+BEGIN_SRC text
     keepassxc-cli search <db> url:smtp.gmail.com:465 user:you@gmail.com
   #+END_SRC

   Terms match as substrings (no exact-match prefix) so this narrows down to
   a small candidate set without assuming the caller passed any particular
   combination of keys; the candidate set is then filtered precisely against
   every key the caller did pass.  A search may therefore give only
   =:host=, only =:user=, host+port, host+user, host+user+port, etc. —
   whatever the caller chose to pass is what is matched.

   Custom attributes (for example a =host= or =port= *attribute* stored on an
   entry) are *not* searchable by keepassxc-cli -- it can only search the five
   canonical fields above.  To make a credential findable, store the server in
   the URL field and the login in the UserName field.
** Example: Gmail SMTP with smtpmail
   A complete, working outgoing-mail setup:

   #+BEGIN_SRC elisp
     (require 'keepass-auth-source)
     (keepass-auth-source-enable)
     (add-to-list 'auth-sources "~/.emacs.d/passwords.kdbx")

     (setq send-mail-function        'smtpmail-send-it
           message-send-mail-function 'smtpmail-send-it
           smtpmail-smtp-server  "smtp.gmail.com"
           smtpmail-smtp-service 465
           smtpmail-stream-type  'ssl
           smtpmail-smtp-user    "you@gmail.com"
           user-mail-address     "you@gmail.com")
   #+END_SRC

   The matching KeePass entry must have its **URL** field set to
   =smtp.gmail.com:465= and its **UserName** field set to =you@gmail.com=.
   (If you omit the port from the search, the URL can just be =smtp.gmail.com=.)

   Note that Gmail requires an [app
   password](https://support.google.com/accounts/answer/185833), not your
   account password.
** Configuration
*** Choosing a backend
   By default the backend is auto-detected.  To force one:

   #+BEGIN_SRC elisp
     (setq keepass-auth-source-cli 'keepassxc) ; keepassxc-cli (default, cross-platform)
     (setq keepass-auth-source-cli 'kpscript)  ; KeePass KPScript (Windows)
   #+END_SRC

   The paths to each external program can also be customized:

   - =keepass-auth-source-keepassxc-cli-program= (default =keepassxc-cli=)
   - =keepass-auth-source-keepass-program=      (default =keepass=)
   - =keepass-auth-source-kpscript-program=       (default =kpscript=)

   All of these are =defcustom=s and can be customized via
   =M-x customize-variable=.
*** Master-password cache expiry
   KeePass database passwords are set to expire after two hours.  This can be
   customized by setting =keepass-auth-source-cache-expiry= to any other value.
   Set it to =nil= to never expire (the master password is then cached for the
   rest of the Emacs session):

   #+BEGIN_SRC elisp
     (setq keepass-auth-source-cache-expiry nil) ; never expire
     (setq keepass-auth-source-cache-expiry 86400) ; one day
   #+END_SRC

   This controls how often you are re-prompted for the KeePass database master
   password.  Even with =nil=, you can force a re-prompt with <kbd>M-x</kbd>
   =keepass-auth-source-forget-cached=.
*** Verbose logging
   To see every =keepassxc-cli= command the backend runs (useful for
   debugging why a lookup narrows the way it does):

   #+BEGIN_SRC elisp
     (setq keepass-auth-source-verbose t)
   #+END_SRC

   Each invocation is logged to =*Messages*= and appended to a
   =*keepass-auth-source-log*= buffer.

   It is normal for a single action (such as sending mail) to trigger
   *several* auth-source lookups, and therefore several keepassxc-cli
   commands.  Emacs's TLS layer and application layers issue separate
   searches with different specs.  For smtpmail specifically you will often
   see two:
     1. a host+port-only search (no user), driven by =network-stream-certificate=
        looking up a TLS certificate for =host:port=, and
     2. the actual credential search with host + user + port.
   Both are legitimate; neither indicates a bug.
*** Suppressing negative caching
   =auth-source= normally remembers every search result -- including an empty
   one -- for =auth-source-cache-expiry= seconds.  A single failure (the
   database is locked, the password was wrong, =keepassxc-cli= was momentarily
   unavailable) therefore keeps every later lookup returning nil long after
   the cause is gone.

   By default keepass-auth-source installs advice so that empty results are
   never cached, so a miss does not stick:

   #+BEGIN_SRC elisp
     (setq keepass-auth-source-suppress-negative-cache t) ; the default
   #+END_SRC
** Clearing the cache
   If you change your KeePass database, change an entry, or re-configure,
   a stale cached value can mask the change.  Run:

   - <kbd>M-x</kbd> =keepass-auth-source-forget-cached= -- forgets the cached
     KeePass *master password*, so the next lookup re-prompts for it.  This
     only touches keepass-auth-source's own cache.
   - <kbd>M-x</kbd> =auth-source-forget-all-cached= -- clears the =auth-source=
     search-result cache.  (This is called automatically by
     =keepass-auth-source-enable=; use it if a *found* result is stale.)
** Testing
   Run the test suite with:

   #+BEGIN_SRC sh
     emacs -Q --batch -L . -l ert -l keepass-auth-source.el \
            -l keepass-auth-source-test.el -f ert-run-tests-batch-and-exit
   #+END_SRC

   The suite includes an integration test that builds a throwaway KeePassXC
   database and queries it; it is skipped if =keepassxc-cli= is not present.
